### System Flow — the round-trip we enabled

```
GH issue body ──prefill (existing artifact pattern)──▶ interactive claude/codex (PTY, worktree, subscription seat)
                                                          │ structured phase writes shipcode-* block
   provider ◀── reads .shipcode/runs/<threadId>/<phase>-output.md ──┘
            └─▶ rawOutput = artifact → existing StreamParser / clarification gate UNCHANGED

`-p` pool exhausted (detect-by-failure) ──▶ flag (24h) ──▶ runtime/getRunMode reroute programmatic claude → interactive
                                                       └─▶ health-check overlay state=blocked → Titlebar badge red + Reset button
```

### Key decisions

- **`-p` rationed, not cut.** Keep programmatic path 100% intact and selectable; default interactive. Reframe = load-shed off a scarce reserve, not amputation.
- **Detect-by-failure, not polling.** No API exposes the `-p` pool balance. `classifyPoolExhaustion` uses a broad, **injectable** matcher (assumption flagged: real error signature unobservable pre-June-15). False positives are cheap (interactive works; flag self-clears in 24h).
- **JSON-file bridge over ANSI scraping.** Structured phases run interactive (raw PTY, no stream-json), so the agent writes its `shipcode-*` block to a gitignored artifact; provider reads it into `rawOutput` so **StreamParser + clarification gate need zero changes**. Raw-transcript fallback for resilience.
- **GitHub = I/O bus (validated direction).** Prefill (issue→prompt) already existed in `issue-terminal-session`; workpad protocol already agent-owned. Read-back via `extractFencedBlock` (provider-agnostic) + `GhCli.listIssueComments`.
- **Strip `ANTHROPIC_API_KEY` from interactive env** (footgun: else it bills API rates and defeats the point).
- **Test harnesses pinned to programmatic** for the structured phases (they assert that still-supported contract); interactive covered by new provider tests.
