## Session 1 — Harmonize board column "Todo" → "Backlog"

Renamed the leftmost board column from **Todo** to **Backlog** across ShipCode's
app, docs, web, and — importantly — the GitHub write/readiness paths, so every
surface matches the vocabulary the dev-loop / `gh-project-board` setup tooling
and the `github-label-sync` skill **already** canonicalize on (`Backlog`). The
investigation that triggered this also surfaced a latent bug: issue creation was
writing GH Projects Status `"Todo"`, which silently fails to match a board whose
canonical option is `"Backlog"`. The internal `todo` pipeline-status slug is
left untouched (no DB migration) — only board-facing/display names moved.
`Agent` / `Attention` columns stay deliberately app-native (they map to GH
`In Progress` / `Human Review`).

### Key decisions

- **Keep internal `todo` slug; rename display only.** Renaming the persisted
  `IssuePipelineStatus.todo` enum would force a DB migration + GH-sync churn for
  zero visible benefit. `GhMacroColumn` value stays `'todo'`; only the
  GitHub/app *display name* becomes "Backlog".
- **One canonical constant, not scattered literals.** The whole reason "Todo" vs
  "Backlog" drifted (skill said Backlog, code said Todo) was scattered string
  literals. `GH_STATUS_OPTION_NAME` is the durable fix against re-drift.
- **`Agent` / `Attention` stay app-native.** They encode "who acts next" + show
  live pipeline sub-states GitHub's flat single-select can't represent; flattening
  to "In Progress"/"Human Review" would lose information and the ShipCode identity.
- **Detection still accepts legacy "Todo" boards** — `TODO_PATTERN` (`todo|backlog|open|triage`)
  unchanged; kept "Todo"-named mapping fixtures in tests to lock this in.
