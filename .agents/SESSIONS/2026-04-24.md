## Session 2 - Dynamic CLI Model Capabilities and Legacy Model Cleanup

**Status:** Complete (`shared`, `agents`, and `desktop` validation passed)

### Context

ShipCode had hardcoded Claude/Codex model options in the app. This was unsafe for Codex because new models such as `gpt-5.5` depend on the installed Codex CLI version. If ShipCode exposed or sent a model that an older CLI did not support, pipeline execution could fail after work had already started.

The target behavior was:

- use the installed CLI's reported model catalog where the CLI can provide one
- avoid advertising `gpt-5.5` unless the local Codex CLI reports it
- keep conservative fallbacks for old CLIs
- validate configured model/effort selections before starting app-level work
- remove misleading legacy code that treated Codex fallback models as an authoritative catalog

### System Flow

```text

real Codex catalog             curated Claude fallback
      |
      v
filter hidden models + parse supported efforts
      |
      v
IntegrationStatus.modelCapabilities
      |
      +-----------------------------+
      |                             |
      v                             v
renderer dropdowns             IPC/app boundary validation
      |                             |
      v                             v
only reported options shown     reject unsupported selection before work starts
```

## Session 4 - Fix Graph Tab React Flow Update Loop

**Status:** Complete (`desktop` typecheck and targeted graph utility test passed)

### Context

The desktop Graph tab was crashing the renderer with:

```text
Error: Maximum update depth exceeded
Component Stack:
  StoreUpdater
  ReactFlow
  ProjectGraphTab
```

The crash happened when opening the new issue dependency Graph tab. The React stack pointed at React Flow's internal store updater, with `ProjectGraphTab` passing values into `ReactFlow`.

### System Flow

```text
open Graph tab
      |
      v
ProjectGraphTab renders ReactFlow
      |
      v
fresh handler props + fresh deleteKeyCode array each render
      |
      v
React Flow StoreUpdater syncs changed props into internal store
      |
      v
selection callback allocates a new selected IDs array
      |
      v
setState even when selection did not actually change
      |
      v
React maximum update depth crash
```

### What Was Done

- [x] Investigated the runtime stack trace and localized the fault surface to `ProjectGraphTab`
- [x] Stabilized React Flow callback props with `useCallback`
- [x] Moved `deleteKeyCode` to a stable module-level constant
- [x] Added selection ID equality checking so unchanged selections do not trigger state updates
- [x] Kept graph layout and IPC behavior unchanged
- [x] Ran formatter on the touched file

### Key Decisions

| Decision | Rationale |
|----------|-----------|
| Fix the React Flow prop/state loop in place | The stack pointed to React Flow's internal `StoreUpdater`; the Graph tab did not need a broader refactor |
| Keep `nodeTypes` and `deleteKeyCode` stable at module scope | React Flow treats prop identity changes as store updates, so stable identities reduce unnecessary synchronization |
| No-op unchanged selection state updates | The selected issue list is derived from React Flow selection; setting a new array with identical IDs can still force another render |
| Leave unrelated dirty worktree changes untouched | The checkout already had unrelated package and UI changes, so this fix stayed scoped to the crash |

### Mistakes and Fixes

## Session 5 - Project Workspace Graph, Git Visualizer, and Settings UX Polish

**Status:** Complete for graph/Git/cursor/settings-modal polish; content-zone Project Settings remains a follow-up

### Context

This session focused on turning the project workspace into a more useful inspection surface:

- the issue graph should live inside the Issues content view, next to list/board controls, not as a top-level project tab
- ShipCode should expose a read-only Git/worktree/diff visualizer similar to Cursor's Git view
- interactive controls should consistently show a pointer cursor
- Project Settings should not show a fake "Back to project" row inside a modal
- the issue graph view needed visual cleanup because React Flow defaults were rendering light UI inside the dark app

### System Flow

```text
Project workspace
      |
      +--> Issues tab
      |       |
      |       +--> board/list/graph toggle in board toolbar
      |       |
      |       +--> graph renders embedded React Flow canvas
      |               |
      |               +--> dark themed minimap / controls / edge labels
      |               +--> opaque issue nodes
      |               +--> floating grouped-run controls only when selected
      |
      +--> Git tab
              |
              +--> IPC loads persisted project worktrees
              +--> Git service reads branch/status/diff for selected worktree
              +--> UI renders read-only worktree list + side-by-side diff
```

### Key Decisions

| Decision | Rationale |
|----------|-----------|
| Put Graph under Issues instead of a top-level tab | Graph is another issue-board representation, not a separate project workspace surface |
| Add Git as a top-level project tab | Worktrees, branches, and diffs are project-wide inspection tools, not issue-board modes |
| Keep Git visualizer read-only | The requested workflow is inspection only; commit/reset/edit controls would increase risk and blur ownership |
| Use persisted worktree paths as source of truth | Matches repo memory: worktree cleanup/inspection must not rederive paths from mutable settings |
| Fix cursor behavior globally and keep primitive cursor classes | `@shipcode/ui` primitives mostly had cursor styles, but the app-level fallback missed anchors and Radix role elements |
| Remove Project Settings back row, but keep shared navigation reusable | Global app settings still need "Back to app"; modal project settings do not |
| Theme React Flow locally under `.shipcode-issue-graph` | The bad minimap/controls came from React Flow defaults, not `@shipshitdev/ui`; scoping avoids broad third-party CSS side effects |
| Remove the graph right rail | The graph canvas is the primary surface; grouped-run actions should appear only when relevant |
| Move Project Settings to content zone later | That is the best UX, but it is a larger refactor than the modal/sidebar cleanup and graph fixes completed here |
