## Session 2 — Grok Build (Grok 4.5) as a first-class execute-only executor

### Context
- User: "do we have any issue about the grok integration. it needs to be done ASAP." + earlier: "we will use grok 4.5 from the cli once available in europe."
- No existing issue → created **#326** (implementation-ready spec), then built it directly (chosen over routing to Codex: local Codex CLI is misconfigured — defaults to gpt-5.6-sol/max the 1.0.3 binary can't serve — and the `codex:codex-rescue` agent type dropped out on session resume).
- Branch `claude/grok-executor-integration`, based on the #325 tip (inherits the Fable/GPT-5.6 catalog it builds on).

### Load-bearing design decision
- **Execute-only, mirroring Cursor.** Confirmed via xAI headless docs: Grok Build's `-p` mode has **no read-only sandbox** flag (only `--always-approve` auto-write). It therefore must not drive plan/review/verify (which the pipeline treats as read-only), or it could mutate the worktree. Added to `EXECUTOR_PHASE_PROVIDERS`, not `VALID_PHASE_PROVIDERS`.

### System flow
```text
AgentType/ExecutorModel += 'grok'
  ├─ model-catalog: GROK_FALLBACK_MODEL_IDS/OPTIONS (grok-4.5), PINNED_MODEL_DEFAULTS.grok, aliases (grok/grok-4.5/grok4.5)
  ├─ model-display: PROVIDER_DISPLAY.grok='Grok', GROK_MODEL_PATTERN /^grok/i, inference branch
  ├─ model-resolution: asExecutorModel + EXECUTOR_PHASE_PROVIDERS (execute-only)
  ├─ reasoning-effort: GROK_REASONING_EFFORTS=['none'] (CLI exposes no effort knob, mirrors cursor)
  ├─ cli-model-capabilities: grok fallback branch + 'Grok CLI' labels
  ├─ constants.PIPELINE_EXECUTOR_PROVIDERS += grok; types/health SystemHealth.grok?
  ├─ agents: grok-cli-provider.ts (execute-only, `grok -p --output-format json --no-auto-update [--model] [--always-approve]`, stdin prompt), providers/index export, registry grok case, AgentProvider id 'grok-cli'
  ├─ health-check: checkGrokAuth (XAI_API_KEY / `grok auth status`), checkGrokModelCapabilities, wired into all capability + system-health aggregators
  └─ apps: desktop main registry + CLI context registry; renderer model-provider-options-data (PROVIDER_DISPLAY.grok='xAI', getModelOptions branch)
```

### Key decisions / assumptions (flagged in PR for verification against the live CLI)
- **Prompt piped on stdin** (like cursor/gemini) rather than as a positional arg — headless docs are pipe/CI-oriented; adjust if the installed CLI requires a positional.
- **`grok auth status`** is a best-effort probe that fails closed (reports unauthenticated) if the subcommand differs; `XAI_API_KEY` is the definitive headless signal.
- **Registered in apps/cli too** (diverges from cursor/gemini, which the CLI omits) because the user explicitly wants Grok "from the cli". Trivially revertible.
- Not added to the automation modal (execute-only, matches cursor/gemini which aren't offered there). Not a project-open target (that's Cursor-the-IDE, unrelated).
- Grok can't be verified end-to-end until EU access (~mid-July); merges now behind the provider abstraction. OpenRouter already accepts `x-ai/grok-4.5` free-text, unchanged.
