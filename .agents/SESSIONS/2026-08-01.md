# 2026-08-01

## Session 1 — Single source of truth for GitHub issue records

Bug report: issue status was hand-synced into two independent stores from two IPC
handlers in `apps/desktop/src/renderer/hooks/useIpc.ts`. Investigation found the
problem was wider than reported — **seven** parallel writers, not two.

### System flow — before and after

```
BEFORE — 7 writers, 2 stores, no owner
  useIpc: pipeline:phase          ──┬─> queryClient.setQueryData(['github-issues', p])
                                    └─> useAppStore.setState({ githubIssues, activeIssue })
  useIpc: github:issues-updated   ──┬─> setQueryData
                                    └─> setState({ githubIssues, activeIssue, activeThreadId })
  IssuesPanel.patchIssueOptimistic──┬─> setQueryData
                                    └─> setGithubIssues
  IssuesPanel useEffect mirror     ───> setGithubIssues   (only while panel mounted)
  CreateIssueModal                 ──┬─> setQueryData
                                    └─> setState
  OverviewView / CostsView /       ───> setGithubIssues   (cache bypassed entirely)
    InboxView  (cross-project nav)
        → board and detail view can disagree about the same issue

AFTER — 1 owner, 1 writer
  every producer ───> queryClient.setQueryData(['github-issues', projectId], …)
                                  │
                    queryCache.subscribe  (issue-cache-projection.ts)
                                  │
                                  ▼
                  useAppStore { githubIssues, activeIssue, activeThreadId }
                        read-only projection · no setter exists
```

### Affected components
- **Renderer stores** — new `issue-cache-projection.ts`; `app-store.ts` loses
  `setGithubIssues`
- **Renderer hooks** — `useIpc.ts` both handlers
- **Renderer components** — `IssuesPanel`, `CreateIssueModal`, `OverviewView`,
  `CostsView`, `InboxView`
- **App shell** — `App.tsx` mounts the projection before `useIpc`

### What was done
- [x] Read every consumer's subscription shape before choosing an owner —
      ~150 `useAppStore.getState()` reads cannot call a hook, so the store field
      has to stay.
- [x] React Query `['github-issues', projectId]` designated the single owner;
      Zustand `githubIssues` / `activeIssue` become a read-only projection.
- [x] New `subscribeIssueCacheProjection(queryClient)` — subscribes to the query
      *cache*, not a `useQuery` result, so it sees every write regardless of what
      is mounted. Also re-derives on `activeProjectId` change.
- [x] All 7 parallel writers collapsed to cache-only writes.
- [x] `setGithubIssues` deleted from the store — the invariant is now enforced by
      the type system, not by convention.
- [x] 7 new tests in `issue-cache-projection.test.ts`; `useIpc.test.tsx` harness
      mounts the projection alongside `useIpc`, mirroring `App.tsx`.
- [x] Typecheck 7/7 clean. Renderer suite 872 passed / 1 unrelated flake.

### Key decisions
- **Full ownership migration, not the `applyIssueStatusUpdate` fallback.** The
  ticket permitted funnelling both handlers through one helper. Rejected: a helper
  keeps two writers in step rather than removing one, which is the drift the ticket
  names. Cache-as-owner removes the second writer outright.
- **Subscribe to the query cache, not a `useQuery` result.** A hook-based mirror
  only runs while its component is mounted — exactly the bug `IssuesPanel`'s
  `useEffect` mirror had. Cache subscription captures fetches, `setQueryData` from
  any component, and optimistic patches alike.
- **Keep the Zustand field as a projection instead of deleting it.** The deeper
  migration (store holds only `activeIssueId`, consumers derive via hooks) would
  churn ~150 call sites across 26 test files. Disproportionate for a drift ticket,
  and the projection already makes drift structurally impossible.
- **Skip projection when the cache entry is `undefined`.** Nothing to derive from,
  and blanking would clobber a selection a navigation action just made.
- **`CreateIssueModal` re-selects explicitly.** The upsert swaps a placeholder id
  for the real one, so the projection cannot carry the selection across; the modal
  calls `selectIssue` itself.
- **Accepted behaviour change:** `pipeline:phase` now nulls an `activeIssue` that
  is absent from the incoming list. Previously it did not; this matches the
  already-tested `github:issues-updated` semantics.

### Mistakes and fixes
- **Typecheck failed on `@testing-library/jest-dom` types.** Fresh worktree with no
  `node_modules`. Fix: `bun install`.
- **`useIpc.test.tsx` throttle test broke.** It queued exactly two `Date.now()`
  values with `mockReturnValueOnce`; the new `setQueryData` seeding in the harness
  consumes one internally (React Query stamps `dataUpdatedAt`). Fix: held
  `mockReturnValue` instead — same throttle-window intent, immune to incidental
  consumers.
- **Ran Biome on a doubled path** after an earlier `cd apps/desktop` — Bash cwd
  persists across calls. Same trap as 2026-07-31. Re-ran from the repo root.
- **`TriageRulesTab.test.tsx` timed out at 16.2s in the full suite.** Green in
  isolation (7 passed, 16.07s) — parallel-load flake, untouched by this change.
