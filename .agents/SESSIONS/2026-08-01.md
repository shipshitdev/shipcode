# 2026-08-01

## Session 1 — SIGKILL escalation was unreachable dead code

`ProcessManager.kill()` marked a process `exited` the instant it *sent* the
signal, so every downstream liveness check saw a corpse that was still running.
The pipeline's 5-second SIGKILL follow-up in `runtime-setup.ts` therefore never
fired once — a child that traps SIGTERM (`trap "" TERM`) outlived the app
forever. The `onAbort` path had no escalation at all.

### System flow — before vs after

```
BEFORE
  kill(id)
    └── send SIGTERM ──► updateState('exited')   ← lie, told synchronously
  runtime-setup: setTimeout(5s) → get(id).state === 'exited' → no SIGKILL  [DEAD]
  child ignoring SIGTERM: orphaned indefinitely

AFTER
  kill(id, signal?, { escalateAfterMs? })
    ├── send signal
    ├── updateState('terminating')          ← new intermediate state
    └── scheduleEscalation(proc, 5_000)     ← default, opt out with 0
          └── on fire: identity-check the ManagedProcess, then SIGKILL

  real pty 'exit' / child 'close'
    └── clearEscalation(id) → updateState('exited')   ← only place 'exited' is set

  runtime-setup timeout AND onAbort → terminate() → processManager.kill(id)
    (escalation owned by the manager: only it sees the real exit event and can
     cancel the pending SIGKILL — the runtime promise has already settled)
```

### Affected components
- **Shared types** — `AgentState` gains `'terminating'` (TS-only union; no zod
  schema validates it at the IPC boundary, so this is not a wire break).
- **Agents** — `process-manager.ts` (escalation timers), `cli-stdin-runner.ts`
  (its own SIGTERM → 5s → SIGKILL for one-shot CLI timeouts).
- **Pipeline** — `runtime-setup.ts` dead inline escalation removed, shared
  `terminate()` used by both timeout and abort.
- **Desktop** — `register-feature-qa-handlers.ts` treats `terminating` as "not a
  server we can hand to the user".

### What was done
- [x] Added `'terminating'` to `AgentState`; audited **every** reader of `state`
      across `packages/` and `apps/desktop/`. `write()` (`=== 'running'`),
      `listActive()`, `killAllAndWait()`, `cleanup()`, `useIpc.ts`,
      `TerminalView.tsx`, `server-lifecycle.ts` are all correct as written; only
      `resize()`, `killStalled()` and the feature-QA handler needed the new arm.
- [x] `kill()` now schedules escalation **by default** (5 s), keyed by id but
      validated against the exact `ManagedProcess` object so a timer can never
      land on a recycled id. Cleared on the real exit in both the pty `onExit`
      and the piped `finalize()` paths.
- [x] `killAllAndWait()` opts out with `escalateAfterMs: 0` — its own grace race
      already owns the batch SIGKILL. Its previously-dead `!== 'exited'` fallback
      is now genuinely reachable.
- [x] 10 fake-timer unit tests in `process-manager.test.ts` + a real-child
      integration suite (`process-manager.escalation.integration.test.ts`) that
      spawns `/bin/sh -c 'trap "" TERM; ...'`, proves it survives SIGTERM, and
      asserts the OS reaped it with `SIGKILL`.
- [x] 2 escalation tests in `cli-stdin-runner.test.ts`.
- [x] Rewrote the two `runtime.test.ts` escalation tests that faked
      `processManager.get()` — that mock is exactly why CI never caught the dead
      code. They now pin the runtime to one polite `kill()` and no SIGKILL.

### Key decisions
- **Escalation is a `kill()` default, not a per-caller opt-in.** Fixes every call
  site including future ones; keeps the timer with the only object that sees the
  real exit event; avoids adding `@shipcode/agents` *value* imports to modules
  whose tests use full-replacement `vi.mock` (that pivot cut the diff from 12
  source files to 5).
- **Only the OS exit event may set `'exited'`.** Anything else reintroduces the
  same class of bug.
- **Assert on the raw `close` signal, not the exit code.** `finalize()` collapses
  every signal death to `130`, so `SIGTERM` vs `SIGKILL` is only distinguishable
  on the child's own `close` payload.

### Mistakes and fixes
- **`git stash` is unsafe in this repo.** `refs/stash` is shared across all
  worktrees, and ~12 concurrent sessions are stashing into it. A `stash -u` →
  test → `stash pop` cycle popped *another session's* stash into this worktree
  and lost this session's WIP from the stash list. Recovered by finding the
  stash commit with `git cat-file --batch-all-objects` and `git stash apply
  <sha>`. **Never `git stash` here — use a scratch commit or a copy instead.**
- Converting an `import type` into a value import dragged `process-manager.ts`
  (which statically imports native `node-pty`) into a test's runtime module
  graph and broke an unrelated suite. Resolved by the design pivot above.
- Local `bun run test` needs `packages/shared|agents|git|db` built first; turbo's
  `test` task does that via `dependsOn: ["^build"]`, a bare `vitest run` does not.
