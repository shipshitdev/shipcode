# 2026-08-01

## Session 1 — one guarded path from main to renderer (`safeSend`)

Bug report: three `webContents.send` calls in `register-github-handlers.ts` bypass
the destroyed-window guard. Widened to the real problem — the repo had **three
different** "safely send to a renderer" idioms and 24 send sites split across them.

### System flow — before and after

```
BEFORE — three idioms, chosen ad hoc per call site
  (a) full guard      isDestroyed() + webContents.isDestroyed() + try/catch
      helpers.ts · update-service.ts · register-support-handlers.ts · pipeline-bridge.ts
  (b) window only     isDestroyed() only, no try/catch, blind to a dead webContents
      notification-service.ts ×5 · index.ts · issue-chat-session.ts
      register-pipeline-handlers.ts · pipeline-scheduler.ts · pipeline-bridge.ts
  (c) nothing         raw send, throws straight out of the IPC handler
      register-github-handlers.ts ×3 · register-project-handlers.ts ×2
      issue-terminal-session.ts · index.ts

  (c) is the reported bug:
    gh api write SUCCEEDS → send throws on destroyed webContents
      → throw escapes the handler → renderer told the write FAILED
      → local cache now disagrees with GitHub

AFTER — one path
  every main-process send → safeSend(window, channel, payload) → boolean
                              ├── canSendToRenderer()  guard
                              └── try/catch            race + HMR-disposed frame
  payload-building work that must be skipped → canSendToRenderer() at the call site
```

### Affected components
- **Main process** — new `safe-send.ts`; 11 modules rerouted
- **IPC handlers** — github, project, support, pipeline, quick-task
- **Services** — notification, update, pipeline-scheduler, pipeline-bridge
- **Sessions** — issue-chat, issue-terminal
- **No renderer, DB, or external surface touched**

### Key decisions
- **Guard *and* try/catch, always.** The check can never be atomic with the send —
  the window can die in between, and dev-mode HMR leaves disposed frames behind.
  Idiom (a) already knew this; (b) and (c) did not.
- **`safeSend` returns `boolean`, and dropping is not an error.** A renderer
  notification is best-effort by definition. If nobody is listening, dropping it is
  the correct outcome — that is the whole fix for the GitHub-write-reported-as-failed bug.
- **Overloads, not one loose signature.** Typed `IpcStreamChannel` overload first,
  `string` fallback second — `pipeline-bridge` forwards `send(event.type, event)` and
  `PipelineEvent` has members (`pipeline:start-context`, `pipeline:approval-gate`)
  that are not `IpcStreamChannels` keys. Mirrors the existing `ShipCodeAPI` precedent.
- **`canSendToRenderer` exists for payload cost, not for sends.** `sendGithubIssuesUpdated`
  does a DB read purely to build its payload; skipping that read for a dead window is a
  real saving and an existing test asserts it. Exported as a type predicate so it narrows.
- **Broader early-returns kept where they guard more than a send** — the two
  `processManager` listeners (normalizer feeding), the notification click handler
  (`restore`/`show`/`focus`). Commented rather than collapsed into `safeSend`.
- **Fixed the test mocks, not the production guard.** The mocks that omitted
  `webContents.isDestroyed` were wrong; adding a `typeof` check to `safeSend` to
  tolerate them would have been the tail wagging the dog.
- **No lint rule to prevent regression.** Biome has no straightforward
  `no-restricted-syntax`; not worth a custom plugin for this diff.

### Mistakes and fixes
- **`git stash` in a worktree popped another session's stash.** `refs/stash` is
  **shared across all worktrees of a repo** — stashing here to compare against a
  clean tree, then popping, restored an unrelated session's `IssuesPanel.tsx` /
  `IssueListView.tsx` work and left mine gone. Recovered via
  `git fsck --unreachable` → located the dangling stash commit by message →
  `git restore --source=<sha>` for tracked files and `--source=<sha>^3` for the
  untracked ones. **Never `git stash` from a worktree** — use `git diff > patch`
  or a scratch clone to get a clean-tree comparison.
- **Edit replaced `try {` with `if (false) {`** in `register-support-handlers.ts`,
  leaving dead code. Caught on re-read, removed.
- **A `cd x && python3 …` chain silently no-opped** because the Bash cwd already
  *was* `x`, so `cd` failed and short-circuited the `&&`. Re-ran without the `cd`
  and added `pwd` + `assert` inside the script. (Same class of bug as 2026-07-31's
  "ran lint from inside the orphan worktree" — Bash cwd persists across calls.)
- **`TS2688 @testing-library/jest-dom`** — fresh worktree had no `node_modules`.
  `bun install` (2221 packages, 8s).

### Gotchas discovered
- **`refs/stash` is repo-global, not worktree-local.** See above. This is the
  second worktree-shared-state footgun in this repo after the orphan worktree.
- **`git-workflows.test.ts` "artifact cleanup" fails on macOS** —
  `/var` vs `/private/var` in temp paths. Same pre-existing PR #488 (`f83c0bc5`)
  symlink issue already logged on 2026-07-31; verified failing on a clean tree.
- **`TriageRulesTab` "rule limit" test times out under full-suite load** —
  renders 50 rule cards in jsdom against a 15s budget. Passes in 3.7s isolated.
  Load-sensitive flake, not a regression.
