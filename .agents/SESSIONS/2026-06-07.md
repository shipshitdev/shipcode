### System Flow — `full.yml` one-dispatch orchestration + caching layers

```
gh workflow run full.yml --ref develop  (workflow_dispatch)
        │
        ▼
   full.yml ──uses:──▶ ci.yml (workflow_call)   ── quality + coverage (ubuntu)
        │                                           ▲ turbo cache + bun store cache
        │  needs: ci (green)
        ▼
        └──uses:──▶ e2e.yml (workflow_call)
                       ├─ lint-typecheck (ubuntu)  ── fast gate, turbo cache
                       └─ desktop-e2e   (macos-15)  ── real Electron suite
                            ▲ turbo cache (^build) + electron-binary cache + bun store
                            └─ default: full suite + flow-coverage gate (authoritative)
                               only_failed=true: playwright --last-failed, gate SKIPPED

pull_request touching .github/workflows/full.yml  (paths-filtered self-test)
        └─▶ children see event_name = pull_request → only LIGHT jobs
            (ci → fast-qa, e2e → web-smoke); heavy macOS suite stays skipped
```

Caching rule applied: **cache hermetic layers (turbo `^build`, bun deps, electron
binary); never cache-skip a green E2E gate.** The E2E turbo tasks are `cache:
false` (non-hermetic — launch real Electron / serve files), so only their build
deps restore from cache; the gate itself always runs.

### Key decisions

- **Cache hermetic layers, never the gate.** Industry standard. The green E2E
  gate always re-runs in full; caching only accelerates its build dependencies.
  `--last-failed` is a dev-loop convenience (opt-in, gate-skipping, flagged
  non-authoritative), never the CI gate.
- **Reject `--only-changed`.** Playwright's `--only-changed` uses the static
  import graph; this suite drives runtime-served Electron-binary / HTTP artifacts
  it does not statically import → unsound. Would silently skip real coverage.
- **Turbo sha key + prefix restore-keys.** Turborepo's official CI pattern: the
  `${{ github.sha }}` key snapshots a fresh `.turbo` each run; `restore-keys`
  prefix grabs the latest. Turbo decides hit/miss by *content hash*, not the
  cache key. Per-job key prefix avoids cross-job save collisions; `runner.os`
  separates Linux/macOS.
- **Orchestrator `uses:` not copy-paste.** `full.yml` invokes `ci.yml` + `e2e.yml`
  as reusable workflows so there's a single source of truth for job logic;
  `needs: ci` enforces ordering. Inside a `workflow_call`, `github.event_name` is
  the caller's event, so a dispatched `full.yml` runs the heavy jobs while its
  PR self-test runs only the light ones.
- **Paths-filtered `pull_request` self-test for develop dispatch.** Avoids
  promoting the suite to master just to make it dispatchable; filtered to
  `full.yml` itself so it never auto-runs the orchestrator on normal PRs. Marked
  for removal once promoted to master.

### Mistakes and fixes

- **Workflow-registration gotcha (the big one).** Assumed pushing `full.yml` with
  a `pull_request` trigger to develop would register it. It did **not** —
  `gh api .../actions/workflows/full.yml` stayed **404** after `3f26a36f`. Root
  cause: GitHub registers a non-default-branch workflow only when one of its
  `pull_request`/`push` triggers **actually fires once**; pushing the file is
  insufficient. Fix: PR #229 *edited* `full.yml`, firing its paths-filtered
  self-test → registered (id `290778929`). e2e.yml had registered earlier only
  because PR #227 fired *its* `pull_request`. Corrected `e2e-ci.md` to record this.
- **`status` is read-only in zsh.** A Monitor poll loop did `status=$(...)` →
  `read-only variable: status`, exit 1. Fixed by renaming loop vars to `st`/`cc`.
- **`only_failed` empty on `pull_request`.** On the self-test event
  `inputs.only_failed` is empty, which fails e2e.yml's boolean `workflow_call`
  input type-check. Fixed preemptively with `${{ inputs.only_failed || false }}`.
- **Bun skips electron postinstall.** Binary absent after `bun install` →
  `require('electron')` throws at launch. Adding electron to `trustedDependencies`
  would churn `bun.lock` and break `--frozen-lockfile`. Fix: run electron's own
  `install.js` explicitly (version-agnostic via `require.resolve`), idempotent
  on a cache hit.
- **PR-status rate-limit banner is cosmetic.** "GitHub API rate limit reached,
  PR status may be out of date" is GraphQL-driven; `gh workflow run` / `gh run
  view` / pushes use REST *core* (5000/hr), which stayed healthy throughout.
