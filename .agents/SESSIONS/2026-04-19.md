### System Flow — Plan Format Retry Context

```
Planning phase attempts plan generation
         |
         v
    Parse response
         |
    [Parse fails?] ─── No ──→ Continue pipeline normally
         |
        Yes
         |
         v
  retryCount < MAX_RETRIES?
         |
        Yes ──→ Save rawOutput to context.previousPlanRawOutput
                         |
                         v
                  startPlanGeneration (retry)
                         |
                         v
                  buildPlanPrompt() appends:
                  - FORMAT_REINFORCEMENT (always)
                  - buildPreviousAttemptContext() (if previousPlanRawOutput set)
                         |
                         v
                  Model sees its own bad output + format correction
```

```
User opens command palette (⌘K)

         |
         v
  allIssues memo combines all results
         |
         v
  Issues group renders above command groups
  User selects issue → navigateToIssue(projectId, issue)
         |
         v
  app-store: switches activeProjectId, sets activeIssue,
  opens terminal if issue is active, closes palette
```

## Session 4 — Issue Rewrite from ShipCode (Freelance Use-Case)

**Status:** Complete

### Context

Freelance use-case: client writes vague GitHub issues; ShipCode needs to AI-rewrite them as structured PRDs, push the updated body back to GitHub, and post a comment tagging the issue author plus a configurable notify handle. Trigger is manual — "Rewrite" button in the IssueDetail pipeline start card.

### System Flow

```
User clicks 'Rewrite' in IssueDetail
  → github:rewrite-issue IPC
    → GhCli.getIssue (fetch current body + author)
    → Read .agents/skills/writing-prds/SKILL.md (or fallback)
    → enhancePrdDraft (AI rewrites body)
    → GhCli.editIssue (push new body to GitHub)
    → build @mention comment (@author + @notifyGithubUser if set)
    → GhCli.addIssueComment (post to GitHub)
    → refresh DB cache + broadcast github:issues-updated
    → return updated GitHubIssueCacheRecord
  → renderer: refreshIssueState, spinner → success/error
```

### Key Decisions

| Decision | Rationale |
|----------|-----------|
| Manual trigger (button), not auto-on-refresh | Explicit control — don't silently overwrite client's issue |
| Tag author + per-project configurable handle | Author always relevant; client handle varies per project |
| `notifyGithubUser` per-project, not global | Different clients → different GitHub handles |
| `addIssueComment` → `spawnWithStdin` | Consistent with all other GH body args; avoids argv limits |
| No DB column for `author` — fetch fresh at rewrite time | `getIssue()` called anyway; avoids extra migration |
| Reuse existing `ai:enhance-prd` skill path + settings | Same PRD skill/model settings — no divergence |
