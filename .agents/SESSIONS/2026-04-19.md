### System Flow — Plan Format Retry Context

```
Planning phase attempts plan generation
         |
         v
    Parse response
         |
    [Parse fails?] ─── No ──→ Continue pipeline normally
         |
        Yes
         |
         v
  retryCount < MAX_RETRIES?
         |
        Yes ──→ Save rawOutput to context.previousPlanRawOutput
                         |
                         v
                  startPlanGeneration (retry)
                         |
                         v
                  buildPlanPrompt() appends:
                  - FORMAT_REINFORCEMENT (always)
                  - buildPreviousAttemptContext() (if previousPlanRawOutput set)
                         |
                         v
                  Model sees its own bad output + format correction
```

### System Flow — Cross-Project Command Palette

```
User opens command palette (⌘K)
         |
         v
  CommandPalette mounts
  useQuery: project:list-visible (enabled only when open)
  useQueries: github:list-issues for each project (enabled only when open)
         |
         v
  allIssues memo combines all results
         |
         v
  Issues group renders above command groups
  User selects issue → navigateToIssue(projectId, issue)
         |
         v
  app-store: switches activeProjectId, sets activeIssue,
  opens terminal if issue is active, closes palette
```

### Key Decisions

| Decision | Rationale |
|----------|-----------|
| FORMAT_REINFORCEMENT appended at end of prompt | End-of-prompt instructions are more reliably followed by GPT-5.x models than mid-prompt |
| previousPlanRawOutput consumed (cleared) after use | One-shot: avoids stale context if a second retry generates a different error |
| Cross-project issue search enabled only when palette open | Avoids unnecessary IPC on mount; prevents test failures from unmocked channels |
| `section` instead of `div[role=region]` for drop zone | Biome enforces useSemanticElements — `section` is the semantic equivalent |
