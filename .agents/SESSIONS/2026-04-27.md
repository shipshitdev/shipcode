## Session 2 - Cloud-Headless-EC2 PRD (Issue #60)

**Status:** Complete (PRD published as GitHub issue, deferred)

### Context

User asked whether shipcode could become a cloud app: Docker on EC2, SSH for ops only, no SaaS, web UI at `shipcode.shipshit.dev` to view and pilot pipeline jobs. The motivation: today shipcode only runs while the user's laptop is on, which kills long-running pipeline loops the moment the lid closes.

Investigation goal:

- map the architectural distance from current Electron desktop shape to a headless cloud shape
- separate "must rebuild" from "lift verbatim"
- write a PRD that the planner phase can later consume cleanly
- park as P3 / deferred for now

### System Flow

```text
user asks "can shipcode run on EC2 with web UI?"
       |
       v
Explore agent maps current shipcode architecture
       |
       +-- main process IPC handlers (apps/desktop/src/main/ipc/)
       +-- renderer bound to window.shipcode (preload contextBridge)
       +-- node:sqlite DB at app.getPath('userData')
       +-- claude/codex/gh CLIs spawned via node-pty
       +-- worktrees already abstracted via AppSettings.worktreeRoot
       +-- apps/web is marketing only, no backend
       +-- single-user-on-localhost auth model
       |
       v
identify portable surface vs Electron-bound surface
       |
       +-- portable: packages/{pipeline, agents, db, git, shared}
       +-- bound:   apps/desktop/src/main/index.ts (Electron bootstrap)
       +-- bound:   apps/desktop/src/preload/index.ts (contextBridge)
       +-- bound:   DB driver (node:sqlite -> better-sqlite3)
       |
       v
write architectural assessment + cutover phases
       |
       +-- Phase A: extract apps/server (Fastify + WS) from main IPC
       +-- Phase B: web control plane replaces preload window.shipcode
       +-- Phase C: Dockerfile + EC2 + reverse-proxy auth
       |
       v
encode as PRD using shipcode writing-prds skill
       |
       v
gh issue create -> issue #60
       |
       v
labels: enhancement, complexity:high, blast:infra, deferred
title prefix: [P3]
```

### Affected Components

- None yet (PRD only). When implemented, the PRD scopes:
  - new `apps/server` package (Fastify + WS, hosts existing IPC handler logic)
  - new web control plane (either rehosted renderer or fresh Vite app under `apps/web`)
  - DB driver swap (`node:sqlite` → `better-sqlite3`)
  - DB path swap (`app.getPath('userData')` → `SHIPCODE_DATA_DIR` env)
  - Dockerfile, EC2 provisioning, Cloudflare Access (or equivalent) auth gate
  - documented one-command deploy

### What Was Done

- [x] Mapped current Electron architecture against a headless cloud target
- [x] Confirmed `packages/{pipeline, agents, db, git, shared}` are pure Node and lift verbatim
- [x] Identified the portable IPC contract at `packages/shared/src/ipc-channels.ts` as the natural HTTP+WS API surface
- [x] Identified worktree path resolution (`packages/shared/src/worktree-path.ts`) as already cloud-friendly via `AppSettings.worktreeRoot`
- [x] Identified `node:sqlite` as the only non-portable DB dependency, swap to `better-sqlite3`
- [x] Identified the auth gate (Cloudflare Access or equivalent reverse-proxy auth) as a non-negotiable requirement before public DNS
- [x] Identified the spend cap as a non-negotiable safety requirement once human-in-the-loop gating is removed
- [x] Drafted PRD using the shipcode `writing-prds` skill conventions:
  - frontmatter (`name`, `description`, `status: backlog`, `estimated_complexity: high`, `blast_radius: infra`)
  - Executive Summary, Problem, Goals, Non-Goals, User Stories, Functional + Non-Functional Requirements
  - Success Criteria mapped to verifiable assertions
  - Out of Scope, Dependencies, Verification Plan, Risks & Open Questions
- [x] Created GitHub issue `#60` with labels `enhancement`, `complexity:high`, `blast:infra`, `deferred` and `[P3]` title prefix

### Key Decisions

| Decision | Rationale |
|----------|-----------|
| Treat the cloud port as a same-monorepo project, not a fork | All pipeline logic is already package-isolated; reusing those packages is the entire point of the current layout |
| Make `apps/server` (new) host the existing IPC handler logic over HTTP+WS | Renderer already talks through a typed `ShipCodeAPI` contract; this contract becomes the API surface with no business-logic changes |
| Defer to `better-sqlite3` for the cloud DB driver | `node:sqlite` requires Electron-bundled Node 22.5+; `better-sqlite3` is drop-in for our sync query layer |
| Require an auth gate before public DNS, even single-user | The cloud control plane can spawn Claude/Codex spend and create real PRs; an unauthenticated public endpoint is unacceptable |
| Require a spend cap as a Functional Requirement, not a nice-to-have | Headless cloud = no human-in-the-loop spend gate between phases; cost runaway is the realistic worst case |
| Keep the Electron desktop app working from the same packages | Cloud is additive; we should not regress local single-user usage to ship a headless variant |
| Park at P3 / `deferred` label | Today shipcode is single-operator, single-machine; the pain is real but not urgent enough to bump priority |
