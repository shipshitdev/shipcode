## Session 3 - Fix `createRequire(import.meta.url)` undefined in CJS bundle

**Status:** Complete (fix landed in `packages/db/src/index.ts`, awaiting `bun dev` restart)

### Context

`bun dev` crashed at Electron main bootstrap:

```
TypeError [ERR_INVALID_ARG_VALUE]: The argument 'filename' must be a file URL object,
file URL string, or absolute path string. Received undefined
    at createRequire (node:internal/modules/cjs/loader:2053:11)
    at Object.<anonymous> (apps/desktop/dist/main/index.js:16935:46)
```

Bundle line read `var _require = (0, node_module.createRequire)({}.url);` — `{}.url` is undefined.

### System Flow

```text
packages/db/src/index.ts (ESM source)
   const _require = createRequire(import.meta.url)
            |
            v
tsc build -> packages/db/dist/index.js (ESM, import.meta.url real)
            |
            v
Vite bundles into apps/desktop/dist/main/index.js (format: cjs)
            |
            v
rollup CJS output rewrites import.meta.url -> {}.url (undefined)
            |
            v
runtime crash on Electron main start
```

### Root Cause

Vite config at `apps/desktop/vite.config.ts:120-129` outputs Electron main as CJS (`formats: ['cjs']`, `output.format: 'cjs'`). Rollup has no real `import.meta.url` in CJS, so it emits the `{}.url` literal placeholder — undefined at runtime. `createRequire(undefined)` throws.

### Fix

`packages/db/src/index.ts:12` — fall back to `__filename` when running CJS:

```ts
const _require = createRequire(
  typeof __filename === 'string' ? __filename : import.meta.url,
);
```

- CJS bundle: `__filename` defined at runtime → ternary picks it.
- Native ESM (tsc dist for tests / direct ESM consumers): `typeof __filename === 'undefined'` → falls through to real `import.meta.url`.
- `typeof` on undeclared identifier returns `'undefined'` without throwing, so the ESM path stays safe.

### Affected Components

- `packages/db/src/index.ts` (single line + comment)
- `packages/db/dist/index.js` (regenerated via `bun run build`)
- `apps/desktop/dist/main/index.js` (regenerated on next `bun dev`)

- [x] Grepped `import.meta.url` / `createRequire` across `packages/` + `apps/desktop/src/` — only hit was `packages/db/src/index.ts:10`
- [x] Edited source to use `__filename` when defined, `import.meta.url` otherwise
- [x] Rebuilt `@shipcode/db` (`bun run build` → tsc), confirmed dist line matches new source
- [x] Told user to restart `bun dev` so Vite re-bundles workspace deps

### Key Decisions

| Decision | Rationale |
|----------|-----------|
| Fix in source, not in Vite config | Single line, no plugin or rollup hack needed; works for any CJS bundler downstream |
| Keep `createRequire` indirection (don't switch to top-level `require('node:sqlite')`) | Preserves the Node-version-guard contract called out in the existing comment — `node:sqlite` must stay lazy so the CLI's Node 22.5 check can fire first |

| Did not externalize `@shipcode/db` from the desktop main bundle | Workspace packages are intentionally bundled; externalizing them would force a runtime resolver and break the single-file Electron main shape |

### System Flow

```text

       |

       |
       +-- pipeline-scheduler.supersedeAll() marks v1 SUPERSEDED   [correct]

renderer IssueDetail.tsx polls plan-history every 15s

phase jumps planning→executing before next 15s tick

       |
       v

       |
       v
=> WTF moment in user's eyes (looks like pipeline ignored failed plan)
```

### Root Cause

**Two issues, not one:**

1. **UI staleness (primary cause of WTF).** `apps/desktop/src/renderer/components/IssueDetail.tsx:124-158` polls `plan-history` only during `PLAN_MUTATING_PHASES` (planning|reviewing|revising). Fast `planning → executing` transition kills polling before v2 fetches into React Query. Stale v1 SUPERSEDED stays visible.
2. **Missing defense-in-depth guard at executor entry.** Today only the TypeScript signature `startExecution(threadId, plan: ShipCodePlan)` blocks null plans at compile time. 11 production call sites — one regression slip + a `tryParsePlan` fallback could hand the executor partial garbage. No runtime DB-source-of-truth gate.

### Fix

**1. Renderer query invalidation** — `apps/desktop/src/renderer/hooks/useIpc.ts:55-67, 102, 136`

Added `invalidatePlanQueriesForThread(threadId)` helper inside `useIpc` effect. Called from:

- `pipeline:phase` handler when `data.threadId === store.activeThreadId` — invalidates immediately on every phase transition for the active thread.
- `plan:parsed` handler unconditionally — invalidates whenever the planner emits a parsed plan, regardless of active thread.

Invalidates both `['plan-history', threadId]` and `['issue-plan-history']` query keys to refetch the currently-rendered plan list and detail panes.

**2. Executor boundary guard** — `packages/pipeline/src/pipeline/execution-phases.ts:131-163`

At top of `startExecution`, after the `if (!context) return;` check, look up the DB record:

```ts
const executionGatePlan = deps.plans.getLatest(threadId);
if (!executionGatePlan) {
  emitPhase(threadId, 'failed', 'Refusing to execute: no plan record found for this thread.');
  activePipelines.delete(threadId);
  return;
}
if (executionGatePlan.structured === null) {
  emitPhase(threadId, 'failed', 'Refusing to execute: latest plan has no parsed structured output.');
  activePipelines.delete(threadId);
  return;
}
if (executionGatePlan.status === 'superseded' || executionGatePlan.status === 'rejected') {
  emitPhase(threadId, 'failed', `Refusing to execute: latest plan is ${executionGatePlan.status}.`);
  activePipelines.delete(threadId);
  return;
}
```

Variable named `executionGatePlan` to avoid collision with existing `latestPlanRecord` at line 260. Function signature unchanged → zero call-site churn.

**3. tryParsePlan fallback observability** — `apps/desktop/src/main/ipc/register-pipeline-handlers.ts:268-283, 364-380, 435-451`

Three IPC handlers (`pipeline:approve`, `pipeline:stabilize`, `pipeline:retry`) re-parse raw output when DB `structured` is null. Wrapped each callsite to:

- only invoke `tryParsePlan` when `latestPlan.structured === null` (was: chained via `??`)
- emit `logEvent('pipeline:plan-parse-fallback', { threadId, planId, source })` when fallback succeeds where the pipeline parser failed

Behaviour unchanged for happy path; divergence between live parser and fallback is now observable in pipeline event logs.

    → useQuery('git:cleanup-analyze') — live gh pr list, dirty probe per worktree
    → user selects items, ticks "I understand" if any remote-branch-merged
    → useMutation('git:cleanup-apply', { itemIds })

### Key decisions

| Decision | Why |
|---|---|
| Use `git status` (not `getDiff`) to enumerate dirty set | `getDiff` only sees tracked unstaged; misses untracked files. Codex review flagged this |
| Strict LLM JSON validator + retry-once + single-commit fallback | Hallucinated filenames, duplicates across groups, and orphans must not silently commit wrong files |
| Per-worktree mutex via in-memory `Map<path, Promise>` | Auto-commit and cleanup both touch worktree state; concurrent runs race |
| Pipeline conflict check via `summary.worktreePath` | Active phase running in same worktree must block auto-commit. Required adding `worktreePath` to ActivePipelineSummary |
| Live `gh pr list` (not DB cache) per cleanup analyze | No `githubPRs` query exists; PRs change frequently; live fetch is fine for ≤200 PRs |
| Dynamic protected branches: defaultBranch + main + master + every active worktree HEAD | User-customized default branches (e.g. `develop`) must be excluded |
| Explicit dirty gate before WorktreeManager.remove | `WorktreeManager.remove` uses `--force`, won't refuse dirty trees on its own |
| `headerActions` slot prop on GitVisualizer | Keep ui package generic; consumer (apps/desktop) decides what buttons render |
| Local `ActiveWorktreeOwner` interface in git-workflows.ts | `@shipcode/shared.ActivePipelineSummary` and `@shipcode/pipeline` lean type don't match; avoid coupling |
| Inline Alert (not toast) for auto-commit result | No toast hook in renderer; `<Alert>` already used in Git tab |
| Reuse `Modal` + `ModalFooter` from `@shipshitdev/ui` | Same pattern as `CreateIssueModal.tsx`, `ProjectSettingsModal.tsx` |
