# 2026-06-16

## Session 1 — Trunk-based migration + CI backbone rewrite

Migrated shipcode from the `develop → staging → master` promotion model to a single
`master` trunk, and rewrote the CI backbone to match genfeed.ai / vitae.ai.

### System flow

```
BEFORE: develop (integration) → staging → master (default + release)
        CI jobs: quality / fast-qa / coverage

AFTER:  master (single trunk, default, protected)
        PR → [Trust Check, Lint, Design System, Typecheck, Test, Secret Scan,
              React Doctor] → squash-merge → push-to-master runs full suite
        Coverage / CodeQL / E2E: cron + dispatch, off the PR hot path
```

### Affected components

- **CI/CD** (`.github/`) — ci.yml, e2e.yml, full.yml, codeql.yml, setup-bun-env composite.
- **Repo settings** (GitHub) — default branch, branch protection, branch deletions.

### Key decisions

- **Trunk-based, not promotion.** Vincent confirmed genfeed.ai/vitae.ai are already trunk;
  shipcode is pre-release so no backward-compat concerns. Single master simplifies the
  cron-from-default-branch rule (weekly E2E/coverage now fire natively).
- **`--affected` only for typecheck/test.** Biome lint + design.md scan the whole repo in
  sub-minute time — affected scoping adds `fetch-depth: 0` cost for no gain there.
- **Coverage/CodeQL off the PR gate.** Slow/occasionally-flaky; cron + dispatch keeps PRs
  fast. CodeQL findings land in the Security tab as advisory SARIF.
- **Required checks = only jobs that always report on a PR.** `web-smoke` (paths-filtered),
  `desktop-e2e`/`Coverage` (skip on PR) excluded — would deadlock the gate.
