# Configuration

## GitHub Labels

Label a GitHub issue with one of the agent labels below and ShipCode will route it to the corresponding executor. Source of truth: [`packages/agents/src/github/model-router.ts`](https://github.com/shipshitdev/shipcode/blob/master/packages/agents/src/github/model-router.ts). Unknown or missing labels fall back to `agent:claude`; multi-agent-label issues return an error.

| Label | Effect |
|-------|--------|
| `agent:claude` | Claude Code implements the issue (default fallback) |
| `agent:codex` | OpenAI Codex implements the issue |
| `agent:openrouter` | OpenRouter executor with default model from your settings |
| `agent:openrouter/auto` | OpenRouter `auto` meta-router — picks the best model per prompt |
| `agent:openrouter/free` | OpenRouter restricted to free-tier models |

## Workflow State

ShipCode does not use GitHub labels for workflow state. Keep workflow state in a typed GitHub
Projects v2 `Status` field, such as `Todo`, `In Progress`, `Done`, and `On hold`.

## Repo Setup Contract

Repos can declare fresh-worktree setup in `.shipcode/setup.json`. This file is read directly from the repo, so desktop and CLI use the same contract.

```json
{
  "version": 1,
  "envFiles": [
    { "source": ".env.local", "required": true }
  ],
  "setupCommands": [
    "bun install --frozen-lockfile"
  ],
  "verifyCommands": [
    "bun run typecheck",
    "bun run test"
  ],
  "setupBeforeVerify": false,
  "testingContext": "Tests use Vitest and live next to source files as *.test.ts."
}
```

- `envFiles`: copied from the repo root into the worktree before execution. Use `target` to write to a different relative path inside the worktree.
- `setupCommands`: run inside the worktree before the execute phase starts.
- `verifyCommands`: run inside the worktree after execute and before the verifier model runs.
- `setupBeforeVerify`: when `true`, reruns `setupCommands` before `verifyCommands`.
- `testingContext`: repo-owned testing guidance injected into the execute prompt.

If the file is missing, ShipCode falls back to the existing per-install settings (`testCommand`, `testingContext`) and current behavior.
