# Mission Control

Mission Control is the global dashboard that lives at the top of the sidebar. It aggregates pipeline state across **all** projects in your workspace, so you can see what's running, what needs attention, and what just completed without switching contexts.

The component is [`apps/desktop/src/renderer/components/DashboardView.tsx`](https://github.com/shipshitdev/shipcode/blob/master/apps/desktop/src/renderer/components/DashboardView.tsx).

## What it shows

- **KPI strip** — active runs, threads awaiting approval, failed threads, threads completed in the last 24h
- **Running by phase** — per-phase counts for planning / reviewing / executing / verifying / shipping
- **Recent activity feed** — chronological stream of phase transitions from every project
- **Alerts** — threads that are stuck, awaiting approval, or have exhausted verification retries

## Click-through

Every row in the feed is clickable. Clicking a row:

1. Switches the active project to the thread's project
2. Fetches that project's issues if they aren't already loaded
3. Opens the IssueDetail overlay for that thread

This is the fastest way to jump from "something failed" to "here's the failure" without manual sidebar navigation.

## Notifications

Mission Control is the UI surface for the notifications system — the same engine that fires OS notifications via `NotificationToaster.tsx`. Configure which events notify in [Settings → Notifications](/desktop/settings):

| Event | Default | Description |
|-------|---------|-------------|
| `awaitingApproval` | on | Pipeline paused after review, waiting for human sign-off |
| `failed` | on | Pipeline errored out |
| `completed` | on | PR successfully opened |
| `verificationExhausted` | on | Verifier exhausted its retry budget without passing |

Toggles for OS notifications, badge counter, and notification sound all live in the same settings section.
